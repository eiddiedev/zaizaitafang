# 新地图接入

先恢复森林底板并验证能运行，再复制为新地图工程。地图生成可能覆盖原场景；请先保留底板备份。若已另建地图，可把底板中的玩法与资源模板节点整体迁移，随后核对挂载，不要只导入塔和怪物模型。

## 需要重新标定的内容

1. `layout_9.lua`：`NativeOrigin`（世界坐标原点）、`NativePoints`（从入口到基地的路线点）、`NativeSlots`、`NativeCore`、`NativeSpawn`、`NativeBounds`、`GetCameraBounds()` 和地形高度采样 `NativeHeights`。当前坐标来自森林，不能直接套在新地形上。
2. 每个塔位保留连续 `id`，填写 `x/z/y`、`route`、沿路线距离 `d`、屏障交点 `wallX/wallZ`、`yaw`、场景节点 `name/editorId`。屏障依赖沿路线的前后关系。
3. `ms-armory_9.lua` 的 `padNames` 必须与新地图塔位顺序、节点名称一致，才能把塔放在石坛顶部。同步检查 `layout.Validate()` 内的路线数量、塔位数量、长度与地图 hash。
4. 重新采样地面高度，核对怪物脚底、仔仔行走、塔顶和水晶落点；只移动场景模型不会自动更新缓存高度数据。
5. 修改地图显示文案、背景环境、出生点和镜头边界，核对手机画幅不露空白。
6. 独立地图发行时检查 `runtime-host_9.lua` 中 `GetOrderedDataStore("CDWavesV1","forest")` 的地图分区、`CDProfileV1` 个人最好成绩分区与平台原生排行榜归属。不要让不同地图混用成绩；新世界的存储/排行能力应在正式环境实测。

## 必须保留的资源

以 `bindings/scene-roots.json` 和 `bindings/assets.json` 为准：

- `晶界守卫` 玩法资源及子节点（主控、UI、声音、世界、特效等）。
- 六类塔的 30 个模板；12 种怪物动画模板。
- `英雄武器与动作组件`、`晶界守卫 · 三职业仔仔职装`。
- `晶界守卫 战斗表现素材V2`，以及原声音节点。
- 平台生成的运行根、资源根、网络同步和官方模块依赖。

模板位于场景上空不代表没有使用。当前运行时会查找、克隆或隐藏它们；直接删除会使塔、怪物、武器、衣服或音效消失。

资产库可用与场景节点绑定完整是两回事。资源 ID/URI 不要凭空替换；如果在新账号或新版本加载失败，在资产库重放对应模型，再核对名称、缩放、朝向、脚本与动画片段。

## 原有规则复用

保持战斗、经济、24 波主线、无限模式、技能、三人协作代码不变。新地图适配完成后，先验证路径与拦截，再做平衡调整。仓库的 `install --mode full` 会恢复整个森林底板，不是向已搭建新地图合并玩法；不要拿它覆盖完成的新地编。
