# 验收与恢复

## 自动检查范围

- 58 个脚本与已保存场景内嵌源码逐字一致。
- SHA-256 校验脚本、场景、环境设置及资源绑定清单。
- 场景 ZIP 完整，所有内部地形/水体引用存在。
- 临时工程的干运行、正式安装、备份、保留目标发布配置、二次校验。
- Lua 5.3 语法、三职业战斗、伤害时序、复活、协作经济、全职业转身、屏障拦截、特效渲染数学和普攻音效路由回归。

这些是离线逻辑和文件迁移测试，不等于手机性能、真实多人网络、云资产下载或第二台电脑的编辑器验收。详见 `tests/last-run.txt` 的实际运行结果。

## 换电脑试玩清单

1. 选职业，检查三个职业武器和服装、原生行走、攻击转身。
2. 检查11个塔位、六类塔升级替换、怪物贴地和行走动画。
3. 检查普攻、技能、魔法塔弹体、炮弹、旧音效与背景音乐。
4. 检查背向攻击转身；屏障前拦截、后方不误挡、首领短暂破壁。
5. 检查准备/倒地/复活/主线通关/无限模式，以及已发布环境的排行榜。
6. 手机检查镜头、拖拽缩放、UI安全区；真实双人/三人检查中途加入与共享金币。

## 恢复备份

安装工具在目标工程旁保存 `project_…-before-gameplay-时间-…` 目录和 `restore.json`，记录本次写入文件。
完全退出编辑器，按清单把备份文件复制回原位置；清单中原本不存在、备份目录也没有的文件，删除此次新增的那份。不要删除清单以外的文件。
工具发生写入异常会尝试自动回滚已触及文件。成功后也应保留备份，直到新电脑实机验收完成。

## 后续提交

在编辑器保存后运行 `tools/export_project.py`，再跑 `tools/transfer.py verify` 与测试；把脚本、场景和 manifest 一起提交。
不要只提交脚本而保留旧场景。只更新已恢复底板的源码可用 `install --mode scripts`（同样需退出编辑器、检查后 `--apply --editor-closed`），重新打开并保存后才会写回场景。
